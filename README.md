# Listen&Talk — 英語発音練習アプリ

（リポジトリ名と公開URLは従来どおり `dictation` のままです）

英文を音読し、Whisper で文字起こしした結果と出題文を比較して発音をチェックするアプリです。
**インストール不要・ブラウザだけで動きます。**

公開URL：**https://tsuzudo.github.io/dictation/**

> **お手本の声は Mac の Chrome を推奨します。** Safari は Premium（高品質）の声を
> Web ページへ渡さないため、選べる声が大きく減ります。iPhone・iPad は Chrome を入れても
> 中身が Safari と同じなので、声の一覧は変わりません。

## 使い方

画面右上で表示言語を切り替えられます（既定は English）。

出題文の選び方は3通りあります。**開くと「スキット」タブが出ます。**

| タブ | 内容 |
|---|---|
| スキット（既定） | 英会話の台詞を会話の流れのまま練習・試聴します（現在14本。下の「スキット発音練習」節） |
| ランダム出題 | 難易度（初級・中級・上級）を選び、`[次の文章を出す]` で1文ずつ出します |
| 自由入力 | 好きな英文を入れて `[この文章で出題]` を押します |

アクセント（米・英・豪）は**お手本の声が変わるだけ**で、判定の厳しさは変わりません。
**スキットタブではアクセントの選択は出ません**（話者A・Bの声を直接選ぶため）。

1. 出題文を出す
2. `[▶ お手本]` で発音を確認する
3. `[● 録音開始]` を押して音読し、話し終えたら `[■ 録音終了]`
4. 文字起こし結果と出題文の差分が**単語単位で色分け表示**されます
5. `[▶ あなたの録音]` で自分の声を聞き返せます

**初回だけ音声モデルのダウンロード（約40MB）が入ります。** 進捗が画面に出ます。
2回目以降はブラウザのキャッシュから読まれるので待ち時間はありません。
録音には**マイクの許可**が必要です（ブラウザが尋ねてきます）。

### スキット発音練習

隣の英会話集（[Aussie English conversation](https://tsuzudo.github.io/Aussie_English_conversation/)）の
台詞を、会話の流れのまま音読する練習です。

一覧から会話を選ぶと**準備画面**が出ます。ここで練習方法を選んでから始めます
（**毎回どれも選ばれていない状態**で出ます。選ぶまで `[練習を始める]` は押せません）。

| 練習方法 | 内容 |
|---|---|
| 全台詞 | すべての台詞を上から順に音読します |
| 役を選ぶ | 自分の役だけ音読します。**相手役の台詞はお手本が自動で読んで**次へ進みます |
| 通しで聞く | 音読せず、会話全体をお手本の声で続けて聞きます |

- `[▼ 訳・解説を見る]` で日本語訳と解説を開けます（既定は閉じたまま）。
  ただし**「通しで聞く」のときは最初から開いた状態**で出ます
- 録音せずに `[スキップ]` で次の台詞へ進めます
- 話者A・話者Bに割り当てる声をそれぞれ選べます（選択は端末に記憶されます）
- 準備画面の `[戻る]` で会話を選び直せます

**「通しで聞く」のときの操作**

- 台詞と台詞の間に 0.5 秒の無音が入ります
- `[一時停止]` で止まります。もう一度押すと**止めた台詞の最初から**鳴らし直します
- 録音はできません（聞くだけのため）
- 最後まで聞いても画面は切り替わりません。**会話全体を見直してから `[終了]`** を押すと
  準備画面へ戻ります

会話のデータは英会話集の公開サイトから読み込みます。**向こうで会話を増やせば、
このアプリ側の作業なしで自動的に増えます**（反映まで最大10分かかります）。

> **iPhone では相手役の自動再生が鳴りません**（iOS が利用者の操作なしの再生を制限して
> いるため）。`[▶ お手本]` を押せば鳴り、練習は最後まで進められます。

## 仕組み

**すべてブラウザ内で完結します。サーバーはありません**（GitHub Pages は静的ファイルを
配信しているだけです）。2026-08-18 に、それまでサーバー側で行っていた文字起こしと判定を
ブラウザへ移しました（spec.txt 9-2節）。

```
録音（getUserMedia / MediaRecorder）
  → 16kHz モノラルへ変換（Web Audio API の OfflineAudioContext）
  → 文字起こし（Transformers.js + Whisper tiny.en・WebAssembly 上で実行）
  → 判定（出題文と単語単位で突き合わせ）
  → 差分を色分け表示
```

- **出題文**：`app/static/sentences.json` をブラウザが読み込み、JavaScript で抽選します
- **文字起こし**：[Transformers.js](https://github.com/huggingface/transformers.js) で
  `Xenova/whisper-tiny.en` を動かします。モデルは初回だけ利用者の端末へダウンロードされ、
  以降はブラウザのキャッシュから読まれます
- **判定**：`app/static/scoring.js`（正規化して単語を対応付け、差分を出す）
- **お手本の読み上げ**：Web Speech API の SpeechSynthesis。実際に鳴る声は端末とブラウザ次第です
- **自分の録音の再生**：録音した音声データをそのまま再生します

**音声も文字起こし結果も端末の外に出ません。** 外部の文字起こしサービスへは送信せず、
サーバーへのアップロードもありません（通信はページとモデルのダウンロードだけです）。

判定時は表記ゆれを許容します（大文字小文字・句読点、`ten` と `10` のような数字表記、
`kg` と `kilogram` のような単位表記）。

> Cloud Run 版（`app.py`）は faster-whisper と difflib をサーバー側で使う構成でしたが、
> **現在は停止しています**（戻り先として残してあります。下の「デプロイ（Google Cloud Run）」節）。

## ローカルでの実行

公開用の配置を組み立ててから、静的ファイルを配信します。**Python のパッケージ導入は不要**です。

```bash
./build_site.sh                      # app/ から _site/ を組み立てる
python3 tests/serve.py 8099 _site    # http://localhost:8099 で配信する
```

`app/` を変更したら、**`build_site.sh` を流し直してください**（`_site/` は古いまま残ります）。

判定ロジックは Python 版（`app/app.py`）と JavaScript 版（`app/static/scoring.js`）の
両方にあります。**どちらかを変えたら必ず一致を確認してください。**

```bash
python3 tests/compare_scoring.py     # 両者の出力が全ケースで一致するか確かめる
```

ブラウザでの動作確認用に `tests/browser_check.html` があります（モデルの読み込み・
文字起こし・判定に加えて、実行デバイスとライブラリのバージョンも検査します）。

### Flask 版をローカルで動かす場合（Cloud Run 版・停止中）

```bash
pip install -r requirements.txt
./run.sh
```

`./run.sh` は Flask サーバーを起動し、Chrome でアプリを開きます（既定は http://127.0.0.1:5001 ）。
**この構成は現在の公開先では使っていません。** 下記の環境変数も Flask 版にだけ効きます。

| 変数 | 既定値 | 説明 |
|---|---|---|
| `PORT` | `5001`（コンテナでは `8080`） | 待ち受けポート |
| `DICTATION_DEBUG` | （無効） | `1` で Flask のデバッグモードを有効化。**公開環境では絶対に有効にしないこと** |
| `DICTATION_WHISPER_MODEL` | `base` | Whisper のモデルサイズ |

## デプロイ（GitHub Pages・現行の公開先）

公開URL：**https://tsuzudo.github.io/dictation/**

`main` へ push すると GitHub Actions（`.github/workflows/pages.yml`）が自動でデプロイします。
手作業は不要です。公開用の配置は `build_site.sh` が `app/` から組み立てます。

```bash
./build_site.sh        # 手元で公開用の配置を確認したいとき（_site/ を作る）
python3 tests/serve.py 8765 <配信ルート>   # 静的配信の確認用サーバー
```

`app/` が唯一の正であり、公開用のファイルを別途持ちません（詳細は spec.txt 9-3節）。

**パスは必ず相対で書くこと。** GitHub Pages はサイトを `/dictation/` 配下に置くため、
`/static/script.js` のような絶対パスはアプリの外を指して 404 になります。

## デプロイ（Google Cloud Run）

> 静的版（GitHub Pages）へ移行後も、戻り先として残しています。
> push しても自動更新はされません。`./deploy.sh` を実行したときだけ反映されます。


`Dockerfile` を使ってコンテナとして動かします。ローカルの `./run.sh` とは独立しています。

```bash
./deploy.sh
```

`./deploy.sh` は「gcloud の設定確認 → デプロイ → 公開URLへの疎通確認」を順に行います。
最後の確認では、デプロイ自体は成功してもアプリが 500 を返している状態を検出するため、
トップページに加えて出題 API も叩きます。

実行しているデプロイコマンドは以下です（引数を変える場合は `deploy.sh` と揃えること）。

```bash
gcloud run deploy dictation \
  --source . \
  --region us-central1 \
  --memory 2Gi \
  --cpu 2 \
  --timeout 300 \
  --allow-unauthenticated
```

- リージョンは無料枠の対象（`us-central1` / `us-east1` / `us-west1`）から選びます
- アクセスが無い間はインスタンスが停止するため、久しぶりの初回アクセスは
  モデル読み込みで十数秒かかります（コールドスタート）
